# SIGLA — Manual Test Cases

**System:** SIGLA (School-Based Information Governance for Life Care Administration)
**Prepared:** 2026-09-11
**Scope:** Functional test cases for every user role, written against the system as deployed against the Railway PostgreSQL database.

Each test case follows one template:

| Field | Meaning |
|---|---|
| **TEST CASE** | What is being tested |
| **PRE-CONDITION(S)** | The state the system and the tester must be in before starting |
| **PROCEDURE(S)** | The steps, in order |
| **SAMPLE TEST DATA** | Values to enter |
| **EXPECTED RESULT** | What the system must do for the test to pass |

**Conventions:**
- "Logged out" means no session — open the login page in a fresh private/incognito window.
- Every dashboard is scoped to the signed-in account's school. A test that says "another school's" needs a second school with its own accounts.
- XLSX exports require the `openspout/openspout` package to be installed (PHP 8.4+); on a machine where it is missing the export button returns an error page. Those cases are marked ⚠.
- Photo scanning (attendance sheets, consent forms) requires `ANTHROPIC_API_KEY` in `.env`; without it the scan control is not rendered. Those cases are marked 🔑.

## Findings while writing these cases

Writing a test case means tracing the path it describes, and one path does not exist.

**F-1 — The Class Adviser cannot submit a deworming request.** `resources/views/adviser-dashboard/deworming.blade.php` posts to `route('dashboard.class-adviser.deworming.store')`, and no such route is registered in `routes/web.php` — nor does any route render that view. The School Nurse's Deworming page (`/dashboard/school-nurse/deworming`) reads and decides on rows in `deworming_requests`, but nothing in the UI creates a row. Effect: SN-18, SN-19 and CA-19 can only be exercised by inserting a request directly. Cases affected are marked ⛔. This is a wiring gap, not a policy decision, and is a one-route fix once the intended submission fields are confirmed.

## Coverage notes

- **Every role has a login test** as the first case, following the given template, plus a logout test.
- **Negative cases** (wrong password, unknown user, unauthorised page, out-of-class learner, over-stock dispensing, future incident date, weekend attendance, unqualified enrolment) are included for each role where the system enforces a rule.
- **Invariants from the codebase** are covered by at least one case each: session-only auth (SN-01…03), the head never writes (SH-04), per-class adviser scope (CA-05, CA-16), one dispensing path (SN-11, CS-05), one attendance write path (FC-04…07), qualifying ≠ enrolment (FC-02, FC-03), at-risk derived from the school's own rule (FC-12, SA-07), encryption at rest (XC-08) and the audit trail (SA-08, XC-09).
- Cases marked ⚠ need `openspout/openspout` installed; cases marked 🔑 need `ANTHROPIC_API_KEY`. They are expected to fail on a machine without those and should be run on one that has them.
