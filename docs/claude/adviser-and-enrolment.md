# Class adviser scope and enrolment

Moved word for word from CLAUDE.md on 2026-11-09. CLAUDE.md keeps the rules most tasks need; this file holds the full rules for the per-section adviser scope, class-list import, the masterlist photo reader, BMI classification and the section catalogue. Mentions of "the … section" may point to a section now in another file under docs/claude/.

### Per-Section Adviser Scope (invariant)

A class adviser is scoped **twice**: to their school, and within it to one class. `assigned_grade_level` + `assigned_section` on their account are the whole scope, and **`App\Support\AdviserClassScope` is the one place that applies it** — `rosterRows()` narrows the session roster, `records()` the database rows, `coversRecord()` tests one learner. Every adviser surface reads through it: the dashboard roster and its three KPI figures, the student profile, the feeding-status page, consent forms, health assessments, medical certificates. Two advisers at the same school never see each other's learners.

The class half of that scope cannot be enforced by the queries, and that is what makes it easy to lose: `school_health_card_records` is deliberately the **whole school** (StudentRosterSync rebuilds it from every learner the institution holds, so the roster survives a session expiry), so each surface has to narrow it itself and one that forgets leaks a colleague's class while every query still looks correct. Three rules hold it together:

- **The narrowing is decided by role, not by whether an assignment happens to be filled in.** The consent-form and health-assessment pickers are shared with the school nurse and clinic staff, who have no class and are entitled to the whole school. The old test — `if ($grade === '' || $section === '') return true;`, copied into four surfaces — served those roles by accident and served an adviser with a missing assignment the same way.
- **For an adviser, a missing assignment yields no learners, never all of them.** An adviser account cannot be approved without both (`required_if:role,class_adviser`), so a session carrying neither is a broken account rather than an adviser of every class. Scope fails closed here for the reason it does in `SchoolHeadOverview` and `FeedingEnrollmentController`.
- **The write is scoped too.** `AdviserController::store` overwrites whatever grade/section was posted with the session's own, and its record lookup is keyed on **LRN alone** — so it also refuses an LRN already enrolled in another class at that school. Without that, submitting a colleague's learner overwrote their record and moved the learner into the submitting adviser's class. Enrolling a new learner is unaffected; a learner genuinely moving between sections has no path here and never did, which is a known gap rather than a decision.

`AdviserClassScopeTest` guards all of it.

**Enrolment has one write path, and every way of reading a class list goes through it.** `AdviserController::enrolLearner()` is the one place a learner is classified, scoped, written to the session roster and persisted, and **`placeRows()` is the one loop that feeds it a list** (it replaced `placeRows()`, and every list now arrives through the handover's preview and confirm) — same rules, same `applyAssignedClass()`, same refusal of an LRN belonging to another class, same audit entry. Three surfaces reach it: `store()` (the form), `import()` (a CSV/XLSX class list, `adviser.import`, read by `App\Support\StudentImportSheet` — header row matched by name, CSV natively, XLSX via OpenSpout) and `scanMasterlist()` (a photographed or scanned masterlist, below). A fourth way of *reading* a class list means calling `placeRows()`, never copying it. **What the two do not share is completeness, and deliberately so.** The form runs `enrolmentRules()`; the import runs `importRules()`, which is that same set with the School Health Card half — birth date, birthplace, guardian, address, contact number, height, weight — downgraded from `required` to `nullable`. The reason is the document: a DepEd **CLASS MASTERLIST** carries `NO / Name / LRN / REMARKS` and nothing else, it is the sheet a school actually holds at the start of a year, and demanding a guardian and a weight of it meant the one file every adviser has could never be uploaded. Everything that makes the import *safe* is still shared and still enforced — the same write path, the same `applyAssignedClass()` scoping to the adviser's own class, the same refusal of an LRN belonging to another class, the same type and length rules. So a spreadsheet is still not a way around the rules; it is a way to start a learner's record before the measuring has happened. A value the sheet *did* give and that cannot be read is still an error (`birth_date` is checked as `date_format:Y-m-d`), because absent and unreadable are different answers. A half-filled learner is not a silent state: `StudentDataCompleteness` already names every one of those fields and the adviser's own dashboard already counts the learners still missing them. A row that fails is skipped and reported by its line number in the `import_report` flash; the rest are enrolled, the existing rows for every LRN on the sheet are fetched in **one** query, and the session is written once. The sheet carries no Sheet 1 history or Sheet 2, so a re-import keeps an existing learner's; the nurse's examination and the coordinator's attendance are never touched. **The reader knows three things about a masterlist that a flat sheet does not have.** Its three name columns are headed by one *merged caption* ("Student's Name (Last Name, First Name Middle Initial)"), and a merged cell hands its value to its top-left position and leaves the span empty — so `expandMergedNameCaption()` reads a caption naming both a last and a first name followed by blank headings as last / first / middle across those columns. A caption *not* followed by blanks is left alone: that is a single full-name column, and "DELA CRUZ JUAN P." cannot be split into a surname and a given name without guessing. Its header is also **stacked over two rows** — `NO`, `LRN` and `REMARKS` merged down the pair, the name columns carrying a band heading on the first line and the caption on the second — so the row the reader finds `LRN` on is not always the row that names the name columns; `readNameColumns()` looks at the line below and, **only where that line is itself a caption**, takes the columns from it and consumes it with the header, or the caption would be read as a learner surnamed "Student's Name (Last Name, First Name Middle Initial)". A row that is not a caption leaves the columns untouched and the sheet is reported unreadable, which is the honest answer. And the sheet has **no Sex column** — it lists the boys under a row reading `MALE` and the girls under one reading `FEMALE` — so `sexBandIn()` reads a row whose only content is one of those two as a band and gives its sex to every learner beneath it, filling only a blank, since a sheet that states a learner's sex outright outranks the heading they are listed under. A band is never a learner and a learner is never a band: a row carrying anything else is read as a learner, so a surname of "Male" is safe. The letterhead above the header, the spacer rows and the adviser's signature under the list all fall out as rows with nothing in the mapped columns. **A learner nobody has measured is stored unmeasured** — `weight`, `bmi_value` and `nutritional_status` are nullable (`2026_09_22_000001_allow_unmeasured_learners_on_student_health_records`) and `measurementOrNull()` writes NULL rather than 0, because a fabricated weight does not stay in its column: it becomes a BMI, then a status, then a learner the feeding programme qualifies, then a cell in the grid the School Head exports. The Enroll Student panel offers the import above the single-learner form (hidden while editing — an edit is one learner) and a template at `adviser.import.template`. **The template is the school's own CLASS MASTERLIST, not a sheet this app invented** (`App\Support\ClassMasterlistTemplate`, written as XLSX through OpenSpout by `importTemplate()`): the letterhead, `CLASS MASTERLIST`, the grade and section, the school year, the stacked header with its merged name caption, the `MALE` and `FEMALE` bands with their own numbering, and the adviser's signature. It used to be a flat twelve-column CSV — LRN, names, birth date, birthplace, guardian, address, contact, height, weight — which no school keeps, so the one document every class already holds was not what the button handed them and the feature only worked for a list somebody had retyped by hand. The wider set of columns is unaffected: `StudentImportSheet::HEADERS` still recognises every one of them, so a sheet exported from another system uploads exactly as before; what changed is which sheet is *offered*. The template is headed from `SchoolLetterhead` and the session's own class, and a school with no address, a session with no assignment and an adviser with no name each print an **empty line to write on**, never an invented value. It is `.xlsx` and not `.csv` for the reason every other export here is, plus one of its own: a ruled form with merged headings does not survive comma-separated text at all. The template and the reader are one contract, so `AdviserStudentImportTest` feeds the downloaded file straight back into `StudentImportSheet` — never change one side's caption wording, header stacking or band rows without the other. `AdviserStudentImportTest` guards it.

**The same masterlist is also read as a photograph, through the same one control, and a document that is not it enrols nobody** (`App\Support\MasterlistSheetScanner`, Gemini vision over the REST API through the `Http` facade — no new SDK). The form on the adviser's desk, photographed or scanned (JPEG/PNG/WebP/PDF), instead of a workbook somebody has to build first. **There is one file picker and one endpoint, not two.** `adviser.import` takes both and `import()` decides which reader runs from `MasterlistSheetScanner::handles($file)` — a teacher should not have to declare which kind of file they are holding before choosing it, and a second input beside the first was two doors into one room. The photo formats join the `mimes:` list and the `accept` attribute **only where a key is set**, so an upload can never be taken and then refused for want of one; a picture posted anyway fails validation rather than half-running. It returns rows shaped exactly like `StudentImportSheet`'s, so they go through `placeRows()` and the camera is a second way to *read* a class list, never a second way to write a learner. Name, LRN and sex are what a masterlist carries, so they are what Sheet 1 is filled with; everything else stays empty and is counted by `StudentDataCompleteness` exactly as it is for the spreadsheet. Four rules:
- **The model reports; the server decides whether this is the form.** It is asked what it *read* — the heading lines, the name caption, the column headings, the band rows — and **`ClassMasterlistTemplate::mismatches()`** rules on it, against the four things `StudentImportSheet` needs to find a learner at all. A model asked "is this a class masterlist?" says yes to an SBFP Master List of Beneficiaries, a seating chart, last year's grade sheet — and each would enrol a class's worth of wrong learners. Its own verdict is taken as well, but **only ever to refuse, never to admit**. It is the same split the section catalogue keeps when it re-checks a dropdown server-side.
- **A refusal writes nothing, and names what was missing.** The check runs before a single row is written, so there is no partial state to undo.
- **Unreadable is not absent.** A learner whose name or LRN could not be read is reported against their line, never written with a guessed value: an LRN is the key of a child's health record, so a transposed digit is a new learner nobody notices. The prompt tells the model to leave a field blank rather than complete it, and `lrn()` refuses anything that is not digits after separators are stripped — `12970819O295` is a reading, not an identifier. The rest of the class is still enrolled.
- **The bands are where sex comes from**, exactly as `sexBandIn()` reads them off the spreadsheet — the form has no Sex column.

Unlike the attendance scanner, an accepted read *is* written: an adviser uploading their own class list is enrolling learners they are responsible for, every field lands on a record they can correct, and nothing here decides whether a child is fed. Requires `GEMINI_API_KEY`; with none the picker offers spreadsheets only **and** the rules refuse a picture regardless, since a control that is not rendered is not a guarantee. The model id is `services.gemini.model` (`GEMINI_MODEL`) rather than a constant, because it is the one thing here that changes without the code changing. A busy reader answers 503 often enough to be ordinary, so the call **retries three times** on the transient statuses (408/429/500/502/503/504) and never on a 400 or 404 — those are answers, and asking again gets the same one — and a retry that runs out is reported as "the reader is busy", never as a status code. `AdviserMasterlistScanTest` guards all of it with the provider faked, and **`phpunit.xml` blanks `GEMINI_API_KEY` and `ANTHROPIC_API_KEY`** the way it blanks `DB_URL`: a developer with a real key must not run a different suite from CI, and no test may reach a provider. **BMI-for-age and height-for-age are classified once, in `App\Support\BmiClassifier`, against the WHO 2007 growth reference for the learner's sex and age in months — never the adult cut-offs (invariant).** It used to apply BMI < 16 / < 18.5 / ≥ 25 to children and a made-up 70 cm + 5 cm-a-year height line, which a tester showed filed learners one category too low (a boy of 15y5m at BMI 15.22 is Wasted, not Severely Wasted; one of 14y7m at 16.4 is Normal, not Wasted) — and the status decides who the feeding programme qualifies. `App\Support\WhoGrowthReference` reads WHO's own LMS tables, kept byte for byte in `resources/data/who2007/` (`.gitattributes` marks them `-text`; `WhoGrowthReferenceTest` pins their checksums and checks every z-score against the ones WHO computed for its AnthroPlus sample survey, `tests/Fixtures/who2007-survey-zscores.csv`), and computes z exactly as AnthroPlus does: age = days ÷ 30.4375, L/M/S interpolated between months, the restricted BMI z beyond ±3 SD, rounded to 2 dp. DepEd scale: BMI z < −3 Severely Wasted, < −2 Wasted, ≤ +1 Normal, ≤ +2 Overweight, else Obese; height z < −3 Severely Stunted, < −2 Stunted, ≤ +2 Normal Height-for-Age, else Tall. **Age comes from the birth date on the record and the weigh-in date** (`ageAtMeasurement()`); only a record with no birth date falls back to completed years read at the middle of that year (× 12 + 6). **No sex or no age is "Not enough data"**, never a status read off the wrong table; a learner past 19 is read at 228 months, where WHO built the reference to meet the adult cut-offs. The forms' live preview is `partials/who-growth-script`, handed the same table through `WhoGrowthReference::forClient()` — never type thresholds into a view again; three copies of them, no two agreeing, is what this replaced. Statuses stored before the fix are re-read by `php artisan nutrition:reclassify` (`--dry-run` first; `NutritionalStatusReclassification`): through the model so every change is audited, never touching enrolment (it reports enrolled learners who no longer qualify, for the coordinator), and leaving a learner with no sex or birth date on file unchanged and listed. `BmiForAgeClassificationTest` and `NutritionReclassifyCommandTest` guard it. **A height and weight no learner could have is refused at entry** (`App\Support\MeasurementPlausibility`, WHO's AnthroPlus flags: BMI-for-age beyond ±5 SD, height-for-age beyond ±6 SD; with no sex or age, a BMI under 10 or over 60) — on Enroll Student / Edit Profile, a class-list row that gives measurements, and the baseline and endline endpoints, with the same limits and wording in the forms' preview (`WhoGrowth.problems`, through `setCustomValidity`). A tester's 187 cm / BMI 2.52 had been filed Severely Wasted. `MeasurementPlausibilityTest` guards it. The DepEd scale has no Underweight column, so the classifier never emits that word. **The retired label is folded at one place, not by every caller:** `FeedingBeneficiarySummary::normalize()` returns Wasted for it, so nothing downstream can emit the word — `statusOf()`, `SchoolHeadOverview::toScale()`, `filterStatus()` and `FeedingReportNarrative::scaleStatus()` each used to re-fold it afterwards, and a fifth caller that forgot would have printed it on a screen. The matchers that recognise `underweight` in a stored value stay (a legacy record must still count as Wasted rather than falling through to Normal); what is gone is any path that *renders* it. The Nutrition Coordinator's reports carry the DepEd scale's four columns with no Underweight bucket, and the adviser dashboard counts those learners in its Wasted figure rather than in a total of its own that was shown nowhere.

Which makes the pair a **choice, not a typed answer**: "MATIYAGA", "Matiyaga" and "Matiyaga " are three different classes to every one of those filters, so an adviser who mistypes their own section silently gets an empty roster they cannot explain.

- **`institution_sections`** is each school's own published list — `institution_id` + `grade_level` + `name`, unique together. Nothing here is personal information (a section name is school structure, not a fact about a child), so every column is plain and may be used in SQL. `InstitutionSectionSeeder` carries Sta. Ana National High School's four grades transcribed from its section report.
- Registration cascades: picking a school loads `api.institutions.sections`, which fills the grade dropdown from the grades that school actually runs and the section dropdown from the grade chosen. `grade_level` uses the same `"Grade 7"` label the roster stores in its section string, so a catalogue choice and an adviser's assignment compare directly.
- The server re-checks it — `InstitutionSection::canonical()` in the `account.request.submit` route — and **stores the catalogue's own spelling**, so every adviser at one school is scoped by the same string no matter how they typed it. Never trust the dropdown alone.
- **A school with no catalogue is accepted as typed.** Not every school has published its sections, and refusing them a registration would be worse than accepting a typed answer, so the form falls back to the generic grade list and a text box. Never make the catalogue a hard requirement for registering.
- `InstitutionSectionCatalogTest` guards this, including the two-advisers-one-school separation itself.

### Health history checklist (testers' report #8)

Sheet 1's Allergies and Hospitalization/Surgery boxes each have a detail line that is open whether or not the box is ticked. A detail written for one is the answer that the learner has it, so the box follows it — on save, on every read (`App\Support\HealthHistory::normalize`, used by the save, `StudentRosterSync`, `PriorityHealthRule` and the MLAT) and as it is typed. "wala" / "none" ticks nothing. `data:tester-checks --fix` repairs rows saved before. `TesterReportNovemberTest`.
