# School-year handover and retention

Moved word for word from CLAUDE.md on 2026-11-09. CLAUDE.md keeps the rules most tasks need; this file holds the full rules for the school-year handover and scheduled deletion. Mentions of "the … section" may point to a section now in another file under docs/claude/.

### Promotion Updates, It Never Deletes (invariant)

A learner moving Grade 7 → 8 keeps everything from Grade 7. Their record is not overwritten and not removed — prior-year data stays retrievable and traceable, because a health history that resets each August is not a health history.

The mechanism is the schema's: `student_health_records` is keyed by **`student_id` + `institution_id` + `school_year`**, and each school year is its own row. A row is one learner in one section for one school year — the **placement** of the SIGLA School Year Transition spec (14 Oct 2026). `AdviserController::enrolLearner()` writes the current school year's row only, so placing a learner in a new year writes a **new row** rather than editing last year's.

**The school-year handover (invariant).** Records move between sections and years **by LRN, never by name, and are never re-encoded**. `App\Support\LearnerPlacement` is the one reading of where a learner stands, off the plain placement columns (`left_at`, `end_status`, `wait_grade`, `delete_after`, `joined_at`, `joined_as`, plus `archived_at`/`archived_by`/`archive_reason`; migration `2026_10_22_000001`): their **latest** row is *active* (open — no `left_at`, no `archived_at`), *waiting* (closed at year end as Promoted/Retained; `wait_grade` is the grade they wait for), or *archived*. Active in an earlier year's section means that section was never closed (`UNCLOSED`). `App\Support\SchoolYearTransition` holds every write; `SchoolYearTransitionTest` walks the spec's 14 test cases.

- **Close school year** (`dashboard.class-adviser.close-year`, `SchoolYearTransitionController`): the outgoing adviser gives every learner still in the section one status — Grades 7–9 Promoted / Retained / Transferred out / Dropped out; Grade 10 Completed Grade 10 instead of Promoted (`LearnerPlacement::FINAL_GRADE`, Senior High is out of scope) — with what each does shown beside it, and Submit writes the whole section in **one transaction** (a missing status writes nothing). Promoted → waiting for the next grade, Retained → waiting for the same grade, the rest → archived with `delete_after` = today + `retention.years`. A `section_closures` row closes the section: it is read-only, nobody can be added to it that year (`sectionClosedRefusal()`), and the page shows its learners and status without ever naming where a learner is now. The page closes last year's section first if it was left open past June. A status can be corrected (`class-adviser.close-year.correct`) **until the learner is placed in a new section** (`SchoolYearTransition::canCorrect()`); after that it is the school's.
- **A class masterlist is taken only by the adviser of the section it names.** It must name its section — the class line in its heading (`GRADE 7 - MATATAG`, or labelled `Grade Level:` / `Section:` lines; on a photo, the heading lines the reader copies) or a Grade / Section column on its rows — and every section it names must be the uploader's own (and the grade too, where it states one), compared without regard to case or spacing. Otherwise the upload fails before any preview: nothing is read further, previewed or written, and any earlier preview is discarded. `ClassMasterlistTemplate::classIn()` reads the class and `sectionRefusal()` is the one rule; `StudentImportSheet::read()['classes']` and the scanner's `headings` feed it. Without it, another section's list of the same grade would carry its waiting learners into the wrong class, because a promoted learner waits for a grade, not a section. The downloaded template is headed with the adviser's own class, so it always passes.
- **Start of school year**: the master-list upload (`adviser.import`, spreadsheet or photo) **writes nothing** — it stores a preview in the session (`AdviserController::PREVIEW_KEY`) classifying every LRN through `LearnerPlacement::classify()`: Matched (waiting for this grade → carried over), No match (→ new enrollee), Found in Archived (→ restored, deletion cancelled), Needs checking (waiting for another grade, still active in an unclosed section, or active in another section this year — not added; a move between sections is undefined in the spec and has no path), Already added (nothing), Rejected (LRN missing or not 12 digits, duplicate, unreadable value). `adviser.import.confirm` re-classifies every row against the database and places only rows whose answer has not moved, in one transaction, through `placeRows()` → `enrolLearner()`; a carried-over learner's profile and Sheet 1 history are read off their last row (`carryOver()`), the year's own readings start empty. A name that differs on the list is shown beside SIGLA's and kept until the adviser ticks the change. **Add to my section by LRN** (`adviser.add-to-section`) runs one LRN through the same checks; a new enrollee needs a name. The manual Enroll Student form keeps its own LRN rule but refuses an LRN the school already holds (it points to Add to my section), so it can never re-encode a learner. Enroll and Edit Profile share that one form, which posts `form_mode` (`enrol` / `edit`); on `enrol` a learner already in the section — the same LRN, or the same name through `LearnerPlacement::sameName()` — is refused with "already enrolled" rather than written over, and only `edit` updates a learner on file (a post with no `form_mode` keeps the old update behaviour).
- **Mid-year**: **Mark as Left School** (on the Edit Profile view, `class-adviser.student.left`) archives a learner as Transferred out / Dropped out. **Restore** from the adviser's Archived tab (`class-adviser.archived.restore`) reopens a same-year row in place or carries an earlier-year learner over, and clears `delete_after`.
- **Access follows the learner** (`AdviserClassScope`): an adviser's learners are those whose latest placement is open in their section, checked on every request — `coversRecord()` requires an open, latest row; `rosterRows()` and `StudentRosterSync` drop anyone whose placement this year has closed. `learnerAccess()` answers current / archived (read-only, from the adviser's own Archived tab) / previous / none, and a previous adviser is told only `NO_LONGER_MESSAGE` ("You no longer have access to this record") — not the record, not the new section. The history moves with the learner: the new adviser opens any year of their MLAT and their earlier-year consents (`HealthConsentFormController::classInYear()` lists the adviser's *current* learners' forms for that year), and the adviser they left loses all of it. The School Nurse and the Clinic Teacher read every archived and waiting learner on **Archived Students** (`dashboard.school-nurse.archived`, `dashboard.clinic-teacher.archived`), opening the record read-only through the MLAT's `?view=1` mode. Every learner starts a new year at **No form yet** for consent.
- **Never widen a write to span school years**, and keep the database the only judge of where a learner stands — never the session.
- **Testing another school year (testing aid).** While `app.school_year_testing` is on (`SCHOOL_YEAR_TESTING`; on by default only when `APP_ENV` is local or testing, like the prototype sessions), a teacher's Teaching Assignment in Settings may name **any** school year — five either side of the calendar's, plus every year on record (`WorkingSchoolYear::options()`). It is stored on `accounts.assigned_school_year` (plain; NULL = the calendar's year, so choosing the calendar's year stores NULL and June moves the teacher on as before), synced into the session beside grade and section, and `ParentalConsentForm::currentSchoolYear()` — the one function every model's current year delegates to — returns it **for that teacher's session only** (`WorkingSchoolYear::chosen()`; every other role stays on `calendarSchoolYear()`). That is what lets a learner be closed in Grade 7, carried into next year's Grade 8 and read across both years without waiting for June. Off, a stored year is ignored. `TeacherAssignmentSettingsTest::a_learner_can_be_followed_into_the_next_school_year` guards it.
- **The current school year is one helper (set 2026-11-10, testers' report #4).** `App\Support\SchoolYear` decides it: `calendar()` is today on the school's clock (`SchoolClock`, Asia/Manila — never the server's UTC `now()`, which put 1 June 00:00–08:00 in the old year) with DepEd's June start; `current()` is that, or the testing aid's year for that teacher's session; `ParentalConsentForm::currentSchoolYear()` / `calendarSchoolYear()` delegate to it. **Every school-year dropdown** is `SchoolYear::options()` — the years on record and the current one, so a year that has not begun is offered only once something is filed under it — and **every page opens on** `SchoolYear::pick()`: the year asked for when offered, else the current one, never the newest on record (`SchoolHeadOverview::schoolYears()` / `defaultYear()`, the consent pages, the clinic visualization and both feeding pages). `CurrentSchoolYearTest` guards it.
- **Health Records keeps school years apart (set 2026-11-10).** The page (`dashboard.student-health-records`, nurse / clinic staff / Clinic Teacher) has a **School Year** filter: `SchoolYear::options()` over the school's own years on record (one `DISTINCT school_year` query), opened with `SchoolYear::pick()`. The current year is the session roster, where the clinic works. An earlier year is that year's own rows (`StudentRosterSync::rowsForYear()`, one query, never written to the session), with every learner placed that year, those who left after it included. It is **read only**: no Fill Medical Record (its link is keyed by the session roster's index), no New Consultation, no Record Vital Signs. The profile's year-tied lookups — `student-vitals.show`, `api.student-consent-status`, `api.student-health-assessment` and the MLAT menus — pass `?school_year=`, read through `SchoolYear::askedFor()`, which a class adviser cannot move off the current year. Every write still goes to the current year's row. `HealthRecordsSchoolYearTest` guards it.
- **The Consultation Log and the nurse's Health Assessments keep school years apart (set 2026-11-10).** Both open on the current year and carry a **School Year** filter. A consultation has no `school_year` column: its year is the one its `consulted_at` falls in, June to May (`SchoolYear::containing()`), read as a range (`SchoolYear::bounds()`, school wall-clock, like the page's month and week figures — never a date function), and the dropdown is the years between the school's first and last visit (`SchoolYear::spanning()`, one `min`/`max` aggregate, held to ten years). Every figure, chart and row is the chosen year's; "Total Consultations" is that year's, not all time. An earlier year is **read only** — no New Consultation, no Edit — and swaps This Month / This Week / Today and the weekly trend for the year's conditions and a June-to-May monthly trend, read in one query. Health Assessments filters on its own `school_year` column; an earlier year shows each learner's examination off that year's row and offers no Fill Health Record (it writes the current year). `ClinicSchoolYearTest` guards it.
- **Test rows under years that have not begun** are removed by `php artisan school-year:remove-future` (`App\Support\FutureSchoolYearCleanup`): it lists, per institution, every row filed under a year after the calendar's, the rows attached to those learner rows, a future-only learner's LRN-kept rows, the files, and Teaching Assignments set to such a year — and deletes nothing. `--force` deletes exactly that list (files first, rows by query in one transaction, one audit entry of years and counts, no name or LRN) and resets those assignments to the calendar's year. The current and past years are never touched, sections closed early in the current year included. `FutureSchoolYearCleanupTest` guards it.
- **Until the migration runs** `LearnerPlacement::supported()` is false: every learner reads as active exactly as before, nobody is due for deletion, and the close-year and archive pages say the database has not been updated rather than failing.

**Archive and scheduled deletion** — the one exception to "nothing deletes a record", and it cannot touch a learner in a section or waiting for one. `App\Support\StudentRetention` decides who is due — **latest row archived and `delete_after` on or before today**, nothing else — and `App\Support\StudentRecordPurge` deletes them through `students:purge-expired` (scheduled **daily** in `routes/console.php`; **nothing calls `schedule:run` on the deployment yet**, so in practice it is a command a human runs — `--dry-run` first). Five rules:

- **Restoring cancels the deletion by construction**: a restored learner has no `delete_after` and an open placement. The job asks `StudentRetention::isDue()` again for each learner immediately before deleting.
- **Files first, then rows, retried per learner.** A learner's files are removed before the rows that name them, so no file outlives its row; the rows then go in one transaction, and the learner is retried (`retry(3, …)`) if anything fails — a file already gone is simply not there the second time.
- **Deletion is by query, not by model.** `Auditable` snapshots `attributesToArray()` into the append-only `audit_logs` on every Eloquent delete, so deleting through the model would copy the learner's personal data into the one table this policy cannot reach. `StudentRecordPurge` writes **one audit entry per deletion with the date and a count of items removed — no name, no LRN, no health data**; `StudentRetentionTest::the_audit_entry_keeps_no_personal_details` reads it back decrypted.
- **Everything linked goes** — every placement row, the rows keyed to them or to the LRN (assessments, attendance, follow-ups, conditions, clinic notes, incidents, both consent tables with their exclusions, certificates, photos, FHIR copies) and the learner's **consultation logs** with their photographs. A consultation carries only a typed name, so it is matched as the profile matches it (surname + given name) and deleted **only when no other learner at the school could be the one named**. `medicine_dispenses` stays: it is a stock movement, and deleting it would rewrite the inventory's history.
- **One institution at a time, and the scope is required.** With no institution id the rule reads nothing and the purge deletes nothing.

**One consequence is accepted rather than solved:** a purge changes what a past DepEd return would say, since the BMI grids recompute historical figures from rows that have now gone.

The warning (`Record will be deleted on … if the learner is not enrolled again`) appears on the Nutritional Health Status list for `StudentRetention::NOTICE_ROLES`, and every Archived list shows each learner's deletion date so staff can act before it.
